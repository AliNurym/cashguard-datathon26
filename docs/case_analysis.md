## 2. Датасет (`data/open`)

- 43 файла, 42 разметки, 22 «нарушение» и 20 «без нарушения». Все ролики 464×848 (вертикальные), ~30 fps, длина 11–143 с.
- **Дубликаты:** `Х-4` = `Х-47` (одинаковый md5, разметка 57 с и 68 с, то есть в одном ролике два нарушения); `Х-5` = `Х-48` (оба без нарушения). При кросс-валидации их нельзя разносить по разным фолдам.
- В именах `X-1` и `X-2` стоит латинская X, в остальных кириллическая Х.
- В разметке есть только целые секунды и признак нарушения, типа нет.
- Ракурсов уже минимум четыре: из-за спины кассира, сбоку слева, напротив (стол развёрнут), сбоку с голубым креслом. Кассиров играют две актрисы. В `Х-11` в кадре выключается свет.
- Сцена: стеклянная дверь, стол кассира, счётная машина, ноутбук, телефон, серый сейф, стул клиента. Действующие лица: кассир, клиент, инкассатор (с зелёной сумкой), посторонние.
- Ролики парные: нарушение и корректная версия одного сценария (например, `Х-28` и `Х-29`, `Х-17` и `Х-16`, `Х-2` и `Х-3`).

## 5. Предлагаемая архитектура

```
upload .mov → job queue → decode 2–5 fps
  → калибровка сцены (open-vocab детектор: дверь, стол, сейф, счётная машина, ноутбук)
  → люди: детекция + трекинг + роль по позиции/траектории (кассир / клиент / третий), без лиц
  → объекты и состояния: деньги на столе, зелёная сумка, сейф открыт/закрыт, дверь, кружка, сумка/верхняя одежда
  → движок правил (temporal state machine) → кандидаты событий
  → локальная VLM-верификация кандидатов (8–16 кадров + вопрос по правилу) → описание на русском
  → реестр правил (YAML: id, название, визуальный критерий, НПА + пункт, шаблон описания)
  → JSON по схеме API + 1–3 кадра с разметкой
```

- **Почему гибрид.** Чистая VLM по скользящему окну на 145-секундном ролике упирается в лимит 5 минут и галлюцинирует. Правила дают точный таймкод и объяснимость, а VLM отсекает ложные срабатывания, пишет описание и ловит новые типы через общий чек-лист.
- **Модели (лицензии с коммерческим использованием):** Qwen2.5-VL-7B или Qwen3-VL-8B (Apache 2.0); RT-DETR или D-FINE (Apache 2.0) вместо Ultralytics YOLO (AGPL-3.0, рискованно); OWLv2 или Grounding DINO (Apache 2.0) для зон; ByteTrack (MIT).
- **Устойчивость к ракурсу:** зоны находить автоматически по объектам, а не задавать пикселями; роли определять относительно стола и сейфа; аугментации (перспектива, кроп, отражение, яркость).
- **Вердикт:** порог подбирается на 42 роликах так, чтобы не было пропусков, затем минимизируются ложные срабатывания. Один уверенный кандидат даёт `violation`.
- **Деплой:** машина с GPU, FastAPI с очередью, публичный URL. Вариант на M4 Max через Cloudflare Tunnel рискован: ноутбук должен работать всё время проверки.

## 6. Стратегия под критерии оценки

Каждое действие привязано к баллам. Чего нет в таблице, не делаем.

| Критерий (баллы) | Что делаем | Как проверяем у себя |
|---|---|---|
| Обнаружение (25) | Двухступенчато: события сцены дают кандидатов с высоким recall, локальная VLM подтверждает состояние (деньги на столе, сейф, счётная машина). Пороги ставятся так, чтобы на обучающих роликах не было пропусков, затем срезаются ложные срабатывания | `scripts/evaluate.py`: recall и FP по уникальным видео; отдельно по каждому правилу |
| Локализация (15) | Таймкод = начало нарушающего действия (так размечен датасет: кассир встал или пошёл к двери, человек вошёл, сумка легла на стол). Систематический сдвиг по типу снимаем по обучающим роликам. Кадр-доказательство берём из того же момента, с рамками объектов | MAE таймкода и доля событий в пределах ±1 и ±2 с |
| Классификация (15) | Закрытый реестр типов с названиями на языке норматива; один тип на событие; новые типы — через отдельный вопрос VLM-чек-листа, а не свободный текст | Точность типа по ручной разметке `labels/types.csv` |
| Обоснованность (15) | Только пункты из `docs/npa_registry.md` (сверены дословно). В ответе цитата пункта и ссылка на абзац adilet. Для косвенных норм формулировка «не соответствует требованию», не «запрещено». Ничего про невидимое (проводки, сверка) | Ни одной ссылки вне реестра (тест на реестр) |
| Устойчивость (10) | Зоны и роли ищутся автоматически по объектам, а не пикселями. Проверка на синтетических ракурсах: перспектива, кроп, отражение, яркость. Свои съёмки с другого угла | Метрики на искажённых копиях роликов против оригинала |
| Готовность продукта (10) | Загрузка, статус, результат; таймлайн с метками нарушений и переходом к моменту; кадры «до/после»; показ найденных зон с ручной правкой | Прогон 40 роликов через API без падений, время < 5 мин на самом длинном |
| Техническое решение (10) | Всё локально, лицензии Apache-2.0/MIT, веса упакованы для работы без интернета, кэш признаков (правила перезапускаются без моделей) | Запуск с отключённой сетью |

### Чем отличаемся (только то, что экономит время проверяющему)

- **Таймлайн ролика.** Люди в помещении, входы и выходы, интервалы «сейф открыт» и «деньги на столе», метки нарушений; клик по метке перематывает видео к моменту.
- **Доказательство «до/после».** Для ухода кассира: кадр с кассиром за столом и кадр пустого помещения с теми же деньгами на столе. Плюс короткий фрагмент ±3 с.
- **Норматив дословно.** У каждого нарушения цитата пункта и ссылка на абзац в adilet, а не просто номер.
- **Калибровка новой камеры.** При загрузке показываем найденные стол, сейф и дверь на первом кадре; если ракурс новый и зоны найдены неверно, их можно поправить и пересчитать правила без повторного прогона моделей.
- **Цифры устойчивости.** В питче показываем метрики на синтетически изменённых ракурсах, а не обещание «работает под любым углом».

## 7. Результаты экспериментов (обучающие 40 уникальных роликов)

| Вариант | Accuracy | Recall | FP | Таймкод ±2 с |
|---|---|---|---|---|
| v0: правила на детекторах, оригинал | 0.675 | 8/21 | 0 | 6/9 |
| v0, синтетический «поворот камеры» | 0.575 | 4/21 | 0 | 2/4 |
| v0, зеркальный ракурс | 0.650 | 7/21 | 0 | 5/8 |
| v0 + Qwen3-VL-4B zero-shot (все правила) | 0.600 | 8/21 | 3 | — |

- Zero-shot VLM 4B новых попаданий не дала, только ложные срабатывания: сейф почти всегда «закрыт», голубые купюры путаются с удостоверением. Правила на VLM по умолчанию выключены (`predict.py --vlm ABCDI` для экспериментов).
- Grounding («найди деньги, дай рамку») работает заметно лучше, чем вопросы да/нет; годится для предразметки кадров.
- Пересмотрен тип `Х-2`: это не «пересчёт без машины» (машина использована на 14–15 с), а приём денег без предъявления документа (в норме `Х-3` клиент сначала даёт удостоверение). Норма: Правила № 231, п. 19 пп. 1. Оговорка: допускается идентификация через сервис цифровых документов, поэтому формулировка «предъявление документа на видео не наблюдается».
- Перспектива ломает пороги v0 (скоры OWLv2 проседают, «одна глубина» в долях кадра неверна). Это главный риск для финального видео с другого угла.

### Обученные классификаторы состояний (DINOv2-base заморожен + логистическая регрессия)

Оценка: LOVO — отложен ролик (похожие видео), LOSO — отложен целый ракурс (9 групп, `labels/setups.json`; ближе к финальному видео под другим углом). Тест также на синтетических ракурсах отложенной группы.

| Модель | Разметка | AUC LOVO | AUC LOSO |
|---|---|---|---|
| Сейф открыт/закрыт (кроп сейфа, люди закрашены) | вручную, `labels/safe_state.csv`: 6 роликов с открытием | 0.97 | 0.87–0.92 |
| Деньги на столе (плитки 4×2 кропа стола) | предразметка VLM-grounding, 45/48 верны при проверке, 3 исключены | 0.97 (плитка) | 0.97 (плитка) |

| Вариант | v0 | v1 (+ сейф + деньги) |
|---|---|---|
| Оригинал, LOSO | 8/21, 0 FP | 8/21, 0 FP |
| Оригинал, сейф LOVO | 8/21, 0 FP | 9/21, 0 FP (+X-20) |
| Поворот камеры, LOSO | 4/21, 0 FP | 5/21, 0 FP (+X-4: деньги, потерянные OWL) |
| Поворот / зеркало, сейф LOVO | 4/21 / 7/21 | 6/21 / 8/21, 1 FP (X-21) |

Что выяснилось по ходу:
- Первая версия сейфа выучила «человек у сейфа», а не «дверца открыта» (все позитивы, кроме X-20, с человеком рядом). Помогло закрашивание людей перед эмбеддингом.
- Аугментации сначала применялись только к позитивам — модель выучила «искажённый кадр = класс». Исправлено: одинаково для обоих классов; для плиток денег — аугментация внутри плитки, чтобы не сдвигать метки.
- Правило B — не «сейф открыт N секунд» (в норме X-25 открыт 10 с стоя, X-8/X-14 — со стула), а «кассир стояла у сейфа и отошла, оставив дверцу открытой».
- Деньги: классификатор надёжен в момент входа следующего клиента (истинные ≥ 0.67, норма ≤ 0.43 на всех ракурсах), но не видит X-26 после ухода кассира — там остаётся OWL.
- Главное ограничение — мало позитивов сейфа (3 ракурса). Свои съёмки открытого сейфа с других углов дадут больше, чем любая настройка порогов.
