# CashGuard: выявление нарушений кассовой дисциплины по видео

Материалы по разделу 8 ТЗ Datathon 26 (кейс ForteBank). Сервис анализирует видео кассы, сообщает, есть ли признаки возможного нарушения, и для каждого показывает тип, таймкод, кадры-доказательства, описание увиденного и норму. Результат — подсказка проверяющему, а не юридическое заключение.

## 2. Запуск и использование

Подробно — [docs/service.md](service.md). Коротко:

```bash
uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python -r requirements-service.txt
.venv/bin/python scripts/download_models.py          # веса один раз; дальше сервис работает без интернета
CASHGUARD_API_KEY=<ключ> .venv/bin/uvicorn service.app:app --host 0.0.0.0 --port 8000
```

- **Интерфейс:** загрузить `.mov` → статус обработки → «Нарушение не обнаружено» или «Обнаружены признаки возможных нарушений». Для каждого нарушения: тип, таймкод, описание, норма с цитатой пункта и ссылкой на «Әділет», кадры с разметкой, переход к моменту на видео; под видео — дорожки фактов (люди, сейф, деньги на столе, входы и уходы).
- **API:** `POST /api/v1/analyze` (поле `file`) → `job_id`; `GET /api/v1/jobs/{job_id}` → `processing | done | failed`, при `done` — `verdict` и `violations` по схеме ТЗ.

## 3. Архитектура и подход

```
видео → детекторы (RT-DETRv2 2.5 кадра/с, OWLv2 1 кадр/с)
      → сцена: стол, сейф, дверь, ноутбук находятся автоматически; люди в помещении
        (отсев отражений в стекле и людей за стеклянной стеной); треки; роли кассир/посетитель; поза сидит/стоит
      → события: кассир ушла, вошёл посетитель, кассир вошла в пустую кассу и села, отошла от сейфа,
        сумка легла на стол, стакан у лица
      → состояния в моменты событий:
          OWLv2 (деньги, сумка, личные вещи) · обученные классификаторы (сейф открыт, деньги на столе)
          · локальная VLM по кропу (экран ноутбука, дверь)
      → правила → реестр норм → JSON по схеме ТЗ + 1–3 кадра с рамками
```

**Почему так, а не «VLM смотрит всё видео»:**

- **Точный таймкод.** Его даёт событие сцены: момент ухода, входа, посадки.
- **Скорость и меньше галлюцинаций.** VLM задаётся конкретный вопрос по кропу только в моменты событий: 0–5 вопросов на ролик.
- **Объяснимость.** Каждое нарушение складывается из наблюдаемых фактов («помещение опустело», «на экране открыта таблица»), а не из свободного текста модели.
- **Проверено на деле.** Zero-shot VLM на вопросах «да/нет» о состояниях дала 0 новых находок и 3 ложных срабатывания (раздел 7). Поэтому VLM используется только там, где она надёжна: экран и дверь.

**Таймкод — начало нарушающего действия**, так размечен обучающий датасет. Для ухода это более поздний из моментов «встала со стула» и «закончила стоять у сейфа». Для входа посетителя — его появление у двери.

## 4. Модели

Все модели работают локально, облачные AI-сервисы не используются. Лицензии проверены по карточкам моделей.

| Модель | Роль | Лицензия |
|---|---|---|
| RT-DETRv2 R50 (`PekingU/rtdetr_v2_r50vd`) | люди, ноутбук, стаканы, сумки | Apache-2.0 |
| OWLv2 base (`google/owlv2-base-patch16-ensemble`) | open-vocabulary: стол, дверь, сейф, деньги, зелёная сумка, сумка, одежда | Apache-2.0 |
| DINOv2 base (`facebook/dinov2-base`) | признаки для обученных классификаторов | Apache-2.0 |
| Qwen3-VL-4B-Instruct (`Qwen/Qwen3-VL-4B-Instruct`) | вопросы по кропу: экран ноутбука, дверь; предразметка денег | Apache-2.0 |
| Логистическая регрессия (scikit-learn, BSD-3) | «сейф открыт», «деньги на столе» | обучена командой |

**Дообучение.** Два классификатора поверх замороженного DINOv2:

- **Сейф открыт/закрыт.**
  - Разметка ручная, `labels/safe_state.csv`: открытия в 6 роликах.
  - Перед эмбеддингом люди на кадре закрашиваются серым. Без этого модель училась «человек у сейфа», а не «дверца открыта».
- **Деньги на столе.**
  - Кроп стола делится на 4×2 плитки.
  - Разметка — предразметка VLM-grounding, проверенная глазами: 45 из 48 верны, ошибки исключены.
- **Аугментации** (перспектива, кроп, отражение, свет) одинаковы для обоих классов. Для плиток они применяются внутри плитки, чтобы не сдвигать метки.
- **Оценка:** LOVO (отложен ролик) и LOSO (отложен целый ракурс, 9 групп), плюс синтетические ракурсы (раздел 7).

**Открытые датасеты.** Поиск с проверкой лицензий — [docs/open_datasets.md](open_datasets.md). Открытых данных со сценой «касса банка сверху», с сейфами и с разметкой «через счётную машину» нет. Некоммерческие наборы (MERL Shopping и др.) отброшены.

## 5. Нормативные источники и принцип сопоставления

**Источники** (тексты сверены дословно с ИПС «Әділет», [docs/npa_registry.md](npa_registry.md)):

1. Правила осуществления кассовых операций и операций по инкассации банкнот, монет и ценностей… — постановление Правления НБРК от 29.11.2019 № 231 (МЮ № 19680), <https://adilet.zan.kz/rus/docs/V1900019680>.
2. Правила организации охраны и устройства помещений банков второго уровня… — постановление Правления НБРК от 24.02.2020 № 14 (МЮ № 20075), <https://adilet.zan.kz/rus/docs/V2000020075>.
3. Требования к обеспечению информационной безопасности банков… — постановление Правления АРРФР от 03.04.2026 № 53 (МЮ № 38336), <https://adilet.zan.kz/rus/docs/V2600038336>.
4. Как банковская практика: Процедура предоставления ЭБУ на Онлайн-платформе ForteBank (2025), п. 35 пп. 4 — документ для клиентов, используется только как аналогия ([docs/npa_workstation_lock.md](npa_workstation_lock.md)).

**Принцип:**

- **Один тип — один или несколько пунктов** из реестра `cashguard/registry.py`. Ссылки вне реестра сервис не выдаёт.
- **Прямая и косвенная норма различаются.**
  - Прямая — когда норма описывает само наблюдаемое действие, например «пересчитываются в присутствии клиента».
  - Косвенная — когда норма описывает требование к помещению или системе. Тогда в описании пишется «не соответствует требованию…», а не «запрещено».
- **Описание фиксирует только видимое на видео:** кто, что, когда. Сервис не утверждает того, что нельзя увидеть: проводки, сверку, наличие ключа, содержание документов.

## 6. Типы нарушений

| Тип | Что видно на видео | Как определяется | Норма |
|---|---|---|---|
| **A** Ценности оставлены без присмотра | кассир покинула помещение, на столе наличные или сумка | помещение опустело + деньги (OWLv2 / классификатор) или зелёная сумка на столе | Правила № 231, п. 20 ч. 2 (прямо); п. 22, если шло обслуживание клиента |
| **B** Сейф оставлен открытым | кассир отошла от сейфа (села или вышла), дверца открыта | переход «стояла у сейфа → села/ушла» + классификатор «сейф открыт» перед уходом | Правила № 231, п. 20 ч. 2, п. 80 (косвенно) |
| **C** Наличные прошлой операции открыто на столе | входит следующий посетитель, на столе деньги предыдущего | вход посетителя + деньги на столе | Правила № 231, п. 20 ч. 2 (прямо) |
| **E** Посторонний в кассовом помещении | третий человек при обслуживании или человек на стороне кассира | число людей ≥ 3; посетитель стоит рядом с кассиром на её стороне стола | Правила № 14, п. 8, п. 16 пп. 1; Правила № 231, п. 14, 17 (косвенно) |
| **F** Приём инкассаторской сумки без проверки | сумка легла на стол, инкассатор сразу ушёл | появление сумки + уход принёсшего в пределах 6 с | Правила № 231, п. 24 пп. 3–4, п. 25 (прямо) |
| **G** Личные вещи, напитки на рабочем месте | сумка, верхняя одежда на столе; кассир пьёт из стакана при деньгах | OWLv2 «сумка/одежда» на столе ≥ 2 с; поднятый стакан у человека ≥ 5 детекций за 2 с | Правила № 231, п. 12 (прямо для личных вещей, косвенно для напитков) |
| **H** Дверь кассового помещения не закрыта | кассир вошла в пустую кассу и не закрыла дверь | вход кассира → посадка → VLM по кропу двери, «открыта» в 2 из 3 кадров | Правила № 14, п. 8, п. 16 пп. 1 (косвенно) |
| **L** Компьютер не заблокирован при уходе | кассир ушла, на экране открыта рабочая программа | помещение опустело → VLM по кропу экрана «unlocked» | Требования АРРФР № 53, п. 26 пп. 1, п. 71 пп. 9 (косвенно) |

В реестре описаны, но **автоматически пока не определяются** (сигнал ненадёжен, правило не включено, чтобы не давать ложных срабатываний):

- **D** — приём наличных без проверки на детекторе (Правила № 231, п. 41, п. 19 пп. 2);
- **I** — приём без предъявления документа (п. 19 пп. 1; оговорка: допускается цифровой документ);
- **J** — пересчёт не в присутствии клиента (п. 20 ч. 1).

## 7. Качество на обучающем датасете

40 уникальных роликов: дубликаты по md5 объединены, `Х-4` = `Х-47`, `Х-5` = `Х-48`. 21 ролик с нарушением, 19 без. Модели сейфа и денег проверены на отложенном ракурсе (LOSO), то есть на ракурсе, которого модель не видела.

| Вариант | Найдено нарушений | Ложных срабатываний | Accuracy вердикта | Таймкод ±2 с |
|---|---|---|---|---|
| Оригинальные ролики | 14 из 21 | 0 из 19 | 0.825 | 12 из 15 |
| Синтетический поворот камеры | 11 из 21 | 0 | 0.750 | 6 из 12 |
| Синтетическое зеркало | 13 из 21 | 0 | 0.800 | 11 из 14 |
| Начальный прототип (только детекторы и правила), оригинал | 8 из 21 | 0 | 0.675 | 6 из 9 |
| Zero-shot VLM на всех состояниях (отвергнуто) | 8 из 21 | 3 | 0.600 | — |

Тип нарушения верен в 14 из 14 найденных с уверенной ручной разметкой.

**Сквозная проверка через API** (`scripts/api_e2e.py`) на развёрнутом сервисе <https://136-80-9-18.sslip.io/> (Google Cloud, NVIDIA L4):

- 40 из 40 роликов обработаны, падений и ошибок схемы нет. 401 без ключа и с неверным ключом, 404 на неизвестную задачу; не-видео завершается `failed` без зависания воркера.
- **15 из 21 нарушения, 0 ложных из 19, accuracy 0.85**, тип верен в 14 из 14. Таймкод ±2 с у 13 из 16. Итоговые классификаторы обучены на всех роликах, поэтому эта оценка оптимистичнее LOSO.
- Время от отправки до результата, вместе с загрузкой видео по интернету: медиана 15 с, максимум 63 с (последний прогон, 17.10.2026). Шесть самых длинных роликов, отправленных одновременно, — последний готов через 195 с при лимите 300 с.
- **Проверка локальности:** серверу временно закрыт весь исходящий интернет (правило файрвола; запрос к google.com не проходит). В этом режиме ролики обработаны с тем же результатом. После проверки правило снято.

## 8. Ограничения и известные ошибки

**Пропущенные нарушения обучающего набора и причина:**

- `Х-24` — оставлен чёрный лоток: не похож на купюры, его не видят ни OWLv2, ни классификатор денег.
- `Х-44` — не использован детектор подлинности: жест «вставить купюру в детектор» не определяется надёжно.
- `Х-34` — клиент ушёл до конца пересчёта: «операция ещё идёт» по кадру не видна.
- `Х-2` — приём денег без документа: VLM путает голубые купюры с удостоверением.
- `Х-1`, `Х-13` — нарушение не удалось однозначно определить при разрешении 464×848.

**Сейф (B).** Открытый сейф есть только в 3 ракурсах обучающих данных. На знакомом ракурсе нарушение находится, на новом классификатор почти не срабатывает (зато и ложных не даёт).

**Другой ракурс.** Пороги «одной глубины» и «сидит/стоит» заданы в долях кадра. При сильной перспективе скоры OWLv2 падают, отсюда снижение на синтетическом повороте камеры.

**Отражения в стекле** отсекаются эвристиками: рост фигуры, уровень стола, «двойник» реального человека. Нестандартная стеклянная стена может дать лишнего «человека».

**VLM** отвечает по кропу. Нетипичный экран блокировки (светлый) или нестандартная дверь могут быть прочитаны неверно.

**Таймкод ухода** подобран по 6 уходам кассира. В `Х-11` (кассир долго стоит у двери после выключения света) ошибка ~5 с.

**Производительность.** Очередь обрабатывается одним воркером строго по порядку. На сервере с NVIDIA L4 самый длинный ролик (143 с) обрабатывается примерно за минуту; шесть самых длинных, отправленных разом, укладываются в 195 с. Пачка заметно больше может упереться в лимит 5 минут.

**Аппаратные различия.** На NVIDIA и на Apple результаты отдельных роликов немного отличаются (`Х-1` находится на сервере, `Х-30` — на Mac). Ложное срабатывание, которое дал GPU-сервер (дубль рамки кассира принят за вошедшего), исправлено; итог выше получен после исправления.

**Персональные данные.** Лица не распознаются и не идентифицируются (запрещено ТЗ). Кадры-доказательства содержат изображения людей как есть.

**Нормы.** Для B, E, H, L нормы косвенные: требования к помещению или системе, а не прямой запрет действия кассира. Это отражено в формулировках описаний.

**Интерфейс** по ТЗ работает без авторизации. API защищён ключом.
